# Agent Operating Guide

Этот файл загружается в каждую сессию и в каждого субагента — держи его коротким. Подробности в `docs/`, читать по необходимости:

| Задача | Читать |
|---|---|
| где лежит код экрана/класса | `docs/tv-code-map.md` |
| API, авторизация, миграция на V1 | `docs/anilibria-api-v1-notes.md` |
| release, подпись, versionCode, beta | `docs/tv-mod-build.md` |

## 1. Главное

- Цель — Android TV, модуль `app-tv`. Mobile — только если пользователь попросил или менялся общий `data`.
- Не изобретать процесс сборки: пользоваться скриптами из `scripts/`.
- Кириллица в исходниках — нормальный UTF-8. После правок строк проверить, что нет mojibake (инструментом `Grep` с этим паттерном; `rg` в PowerShell не установлен):
  ```powershell
  rg -n "Рџ|РЎ|Рљ|Р‘|Р’|Рќ|Рћ|Рў|Р—|Р­|Рњ|СЃ|СЊ|С‹|СЂ|С‚|С€|С‡|С‰|СЋ|СЏ|С‘" app-tv/src -S
  ```
- Минимальные правки в существующей архитектуре (repository/api/mapper). Без массовых рефакторингов legacy-кода.
- Вопрос/анализ → сначала предложить решение. Явная задача («сделай», «выполняй план») → делать без лишних согласований.
- Коммитить/пушить только по просьбе пользователя.

## 2. Ветки и worktree

Параллельно работает много сессий, PR постоянно вливаются в `develop` (форк `TOSHIK13/anilibria-app`). Перед реализацией и перед сборкой для ТВ: `git fetch` и rebase на свежий `origin/develop`; проверить `git worktree list` и `git for-each-ref --sort=-committerdate refs/heads` — не переделывать то, что уже есть в более новой ветке.

## 3. Сборка и устройство

Все команды — из корня checkout'а (worktree тоже подходит: тулчейн, keystore и `local.properties` берутся из основного `D:/Ani`).

| Что | Команда |
|---|---|
| TV release APK (эталон) | `powershell -ExecutionPolicy Bypass -File scripts/build-tv-app-release.ps1` (`-Beta` — ставится рядом) → `D:/Ani/release-apks`, печатает SHA256 |
| TV debug APK | `powershell -File scripts/tv/tv.ps1 build` (печатает только ошибки и путь к APK) |
| Mobile debug (при правках `data`) | `. scripts/tv/env.ps1; .\gradlew.bat :app-mobile:assembleAppDebug -q` |
| Установка / запуск | `tv.ps1 install`, `tv.ps1 restart` |
| Устройства | `tv.ps1 devices` |

`scripts/tv/env.ps1` (dot-source) выставляет `JAVA_HOME`, `ANDROID_HOME`, `GRADLE_USER_HOME` и `PATH` — не прописывать их вручную в каждой команде.

Устройства (`-Device`):
- `emu` — эмулятор `emulator-5554`, AVD `Ani_TV_API_36` (`tv.ps1 emu` запускает). Для промежуточных проверок.
- `tv` — реальный ТВ Ugoos UHD Google TV STB, `192.168.1.151:5555`. Для финальной проверки.
- Пакет: `ru.radiationx.anilibria.app.tv.mod`.

«No connected devices!» — не ошибка кода: проверить `tv.ps1 devices`, честно сообщить, если устройства нет.

## 4. Проверка UI на устройстве (дёшево по токенам)

Каждый шаг агента перечитывает весь контекст, а скриншот стоит ~1–1.5k токенов и остаётся в контексте навсегда. Поэтому:
- Фокус и тексты проверять текстом: `tv.ps1 focus` (класс, id, текст, bounds фокуса). Скриншот — только когда важна вёрстка.
- `tv.ps1 shot <name>` уже уменьшает до 960px; для деталей — `-Crop x,y,w,h`. Не читать один и тот же скриншот повторно.
- Навигацию делать одной командой: `tv.ps1 keys "DOWN*3 RIGHT CENTER"` или сценарием `tv.ps1 scenario file.txt` (строки: `keys …`, `wait 2`, `focus`, `shot name`, `log`, `restart`), а не «одна кнопка — один шаг».
- Логи: `tv.ps1 log [-Pattern re] [-Lines N]` — только ошибки процесса приложения, не весь logcat.
- Длинную визуальную проверку отдавать отдельному субагенту (см. §6) — картинки не должны копиться в контексте оркестратора.

## 5. Экономия токенов при работе с кодом

- Искать `Grep`'ом, читать `Read` с `offset`/`limit`. Не делать `cat a.kt b.kt c.kt` целиком. Большие файлы (`ComposePlayerFragment.kt` ~3240 строк, `PlayerViewModel.kt` ~1030) — только кусками.
- Начинать с `docs/tv-code-map.md`, а не с обхода репозитория. Без `gradle sync` и полной индексации.
- Существующие файлы менять `Edit`, а не переписывать `Write` целиком и не Python-скриптами-патчами.
- Вывод команд фильтровать (`-q`, `Select-String`, `Select-Object -Last N`). Большие сохранённые tool-results не читать целиком — грепать.
- Вспомогательные скрипты, нужные больше одного раза, класть в `scripts/tv/`, а не в scratchpad.

## 6. Оркестрация и субагенты

Оркестратор (основная сессия) планирует, раздаёт задачи, интегрирует и проверяет. Он не читает код сам и не гоняет пошаговую UI-проверку — это делают субагенты и возвращают короткую выжимку.

Модель задавать явно (по умолчанию субагент наследует дорогую модель оркестратора):

| Задача субагента | `model` |
|---|---|
| поиск по коду, «где/как устроено» (Explore) | `haiku` |
| проверка на эмуляторе/ТВ по сценарию, сбор логов | `haiku` или `sonnet` |
| реализация этапа по подробному ТЗ | `sonnet` |
| сложная архитектура, неясный баг, дизайн решения | `opus` / наследовать |

Бриф субагенту:
- общий контекст — в файл (`BRIEF.md` в scratchpad), в промпте только ссылка и дельта;
- указывать конкретные файлы/символы из `docs/tv-code-map.md`, чтобы не искал;
- `AGENTS.md` уже загружен у субагента — не просить перечитать;
- ограничить объём: один этап — один субагент; ответ — коротко (что сделано, файлы, результат сборки).

Длинные сессии дорожают квадратично: на границе этапов — новая сессия с handoff-файлом или `/compact`.

## 7. Проблемы окружения ≠ проблемы кода

Окружение (не объявлять патч сломанным): Gradle не находит JDK/SDK/плагин (`Could not resolve org.jetbrains.kotlin.plugin.parcelize…`, `Plugin [id: 'com.android.application'…] was not found`), нет keystore, нет устройства, ошибка до компиляции изменённых модулей. Сначала проверить, что использовались скрипты выше и существуют `D:/Ani/.gradle/codex-tools/{android-sdk,jdk-home.txt,local-release.jks}`.

Код: сборка проходит, но падает рантайм; `JsonDataException`, `HttpException`, 401/403, NPE, ошибки маппинга; ломается конкретный экран.

## 8. Дебаг

Если просят дебаг без правок — код не трогать: воспроизведение, `tv.ps1 log`, сетевые запросы; сначала факты, потом гипотезы. Не переписывать код без подтверждения по логам.

## 9. API (кратко)

- account и anime API — `https://anilibria.top`;
- часть V1 endpoints отдаёт голый массив, часть — `{ data, meta }`; `releases/list` — объект;
- `favorites` и `collections` — разные endpoints; рекомендации — `/api/v1/anime/releases/recommended`;
- OTP code не дополнять и не менять визуально.

Перед новой миграцией — `docs/anilibria-api-v1-notes.md`, не исследовать API заново.

## 10. Источник истины

`AGENTS.md` → `docs/*.md` → реальные скрипты в `scripts/`. При расхождении с привычками агента выбирать workspace.
